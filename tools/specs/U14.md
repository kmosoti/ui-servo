# U14 — Promotion route + end-to-end hero gauntlet round (the proof of concept)

Owned paths: `site/src/fragments/promoted.rs` (+ minimal `site/src/fragments/mod.rs`, `site/src/pages/*.rs` wiring), `site/assets/fragments/` (promoted fragment HTML, tracked in git), `tests/test_promotion.py`, `evidence/` + `exemplars/` artifacts from the demo round, `demo/README.md` (round transcript). READ everything else.

## Deliverables

1. **Promotion serving route (closes the U12 protocol gap).** The site must serve human-picked fragments from `site/assets/fragments/<part>.html`:
   - `fragments::promoted::render(part)` reads `site/assets/fragments/<part>.html` at request time (dev) / startup-cached (release), wraps it in `frame()` so it gets a fresh `data-span-id` + `elementtiming`, and returns 404 for an unknown/missing part.
   - Route `/fragments/promoted/{part}`, and the home page mounts the promoted `hero` when the file exists (falling back to the built-in placeholder when it doesn't) — so a pick visibly changes the real site.
   - **Gate on promotion**: `promoted.rs` must refuse (startup error in release, 500 + logged violation in dev) any promoted file that fails a recorded class-0 check — carry a `<!-- ui-servo: gated round=<n> sha256=<hash> -->` provenance comment written at promotion time, and verify presence; the actual sanitizer runs in Python at promotion, not in Rust.
   - Rust tests: promoted fragment served with span id; missing part 404; provenance-less file refused.
2. **The hero gauntlet round (the PoC).** Run the real loop end-to-end:
   - Write the part spec for `hero` (personal-site hero honoring direction.toml).
   - Generate K=4 candidate fragments across distinct QD cells. Builders: use the three local CLI families where practical (claude/codex/agy) so `builder_family` is real and the self-preference guard is exercised; name files `hero.<family>.<k>.html`. **One candidate must be deliberately gate-broken** (e.g. unknown class + overflow) to prove deterministic pruning.
   - `uv run python -m ui_servo.control.servo --candidates <dir> --part hero --round 1 --out evidence/rounds/1/` with live judges (fall back to `--dry-judges` only if a family is unavailable; record which).
   - Verify: the broken candidate is rejected by gates and never reaches a judge (assert from evidence: no judge signal references its span); survivors are ranked; blind staging shows no family tokens in judge prompts; frontier report renders.
   - Promote the winner to `site/assets/fragments/hero.html` with the provenance comment; confirm the site serves it.
   - `demo/README.md`: the transcript — candidates, gate outcomes, panel verdicts (with selector citations), the pick, and screenshots of before/after.
3. **tests/test_promotion.py**: promoted-file round-trip through the sanitizer + provenance-comment verification; the site serves the promoted hero (Playwright: `/` contains the promoted content and a span id).
